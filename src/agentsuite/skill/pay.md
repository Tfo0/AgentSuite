## 一、确认 | 认哪个字段后端信前端

抓下单/绑券请求,看清金额/数量/券 ID/货 ID 哪个后端信前端(改后应付/实付真变 = 信前端),再逐个改。签约/下单/开通页 RPC 要 `sign`/`signKey` 的,看签名能否被截取(假签回显)或换钥(开通页 RPC 未登录换 signKey)。

## 二、绕过 | 后端信前端字段 或 签名口子可截取才有攻击面 只给思路自由发挥

- **价格**:`price`/`amount` 改 `0.01`/`-100`(负数应退款);改 `discount` 超额/负数。
- **数量**:`count`/`quantity` 改 `-1`(负数→退款)/`2147483647`(Int32 溢出)/`0`(零元下单)。
- **券/积分**:并发提交同一 `couponId`(重复核销/到账);兑换 `points` 改负数应余额增;券 ID 改他人券/已过期券。
- **跨店绑券**:本店建大额无门槛券 → 绑自己的货取请求 → 只改 `productId` 成别店/别品类货,券 ID 不动 → 看 C 端那件货应付价(只后台列表多一行不算,必须 C 端价真变)。
- **促销叠加**:满减+折扣+券叠加绕互斥(本不该叠加的促销同时生效)。
- **竞态(TOCTOU,余额双扣/库存超卖)**:余额/提现 2-3 份并发各扣满额 → 余额为负;库存/限量券同请求 N 并发,N>配额 → 成功数>配额(校验与使用非原子)。
- **假签回显截签**:假签打签约/下单口,GET/DELETE 也 302,Location/报错回 `calculateSign is:` 带服务端刚算的签 → 截取 `sign_data`/`sign` 打查询。
- **开通页 RPC 换 signKey**:未登录换 `appId` → 死应用 `APP_NOT_FOUND`,活应用回完整 `signKey` → 真钥现签打支付进件/改结算卡。

## 三、证明 | 不真下单成交 过了能撤销立刻撤

- 价格/数量/券改后应付价真降/负数退款/零元下单 = 后端信前端成立。
- 跨店绑券:C 端别人货价下降(不是后台列表多一行)。
- 并发:重复核销/超卖订单/余额为负(须可复现,偶发一次不算)。
- 默认只动自己的单,过了能撤销的立刻撤(取消订单/退券),不真下单成交、不真提现到账。
- 假签截取的签打查询成功 / 拿真 signKey 现签打支付进件成功 = 成立(只测查询/进件读,不真改结算卡)。

## 四、误报

- 改 `price` 回 400(后端重算);负数被拒;重复券第一次就作废。
- 跨店绑券:券绑店/品类校验严、改 `productId` 券失效、只后台列表多一行 C 端价没变。
- 并发 N 份只 1 成功其余"已领/duplicate key"=有 UNIQUE 保护;响应阶梯递增=后端串行有锁。
- 假签一律 `SIGN_ERROR` 没回算出的签、截取后重放仍 `ILLEGAL_SIGN`;开通页 RPC 死活都 `APP_NOT_FOUND` 无钥 / 回占位钥过不了验签。
