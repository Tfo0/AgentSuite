## 一、确认 | 未授权 + 探针找字段

1. **未授权**:对话口(`/chat`/`/createTask` 一类)不带 Cookie 仍接受请求;有身份口(whoami/profile)对照应拦,无身份口对照亦可测。
2. **探针找可用字段**(除 `message`/`prompt` 显式字段外,确认后端还接什么;两个思路):
   - **fuzz 提示词**:发 prompt 令模型暴露后端能力——令其调工具,看响应是否出现 `tool_calls`/`function_call`;令其拉取 url,看响应是否有外站内容取回。
   - **fuzz 字段**:直接在请求增字段,查后端是否接受(隐藏字段)。字段名不写死,据上下文发散。
3. **认 tool/url 从流量响应**:看响应 `tool_calls`/`function_call`;SSE/事件流查 tool 回包——仅 delta、无 `toolName` 须继续追查。

## 二、绕过 | 基于探针发现的字段利用 只给思路自由发挥

- **探针发现 tool**:指定工具执行无害标记(令模型用 bash/Python 执行 `id`/`echo 标记 && id`)。不应只问"请执行"而不指定工具。`id` 仅证命令执行,须进一步追查。
- **探针发现 url**:参填外站 URL,查服务端是否将外站内容取回对话(经 LLM 工具触发 SSRF 的入口)。
- **追查目标**:命令执行后追查——云元数据/临时钥;沙箱内主体业务正文(对话历史、工单、密钥文件)。公网首页不视为通达内网。
- **令模型调越权工具**:LLM 决策被操纵时调 fetch 访问内网、调 sql 执行注入、调 exec 执行命令(下游 SSRF/SQLi/RCE 经 LLM 工具触发,只描述攻击链)。有会话时同法仍测:身份既过,对话口工具是否仍接受所编命令。

## 三、证明 | 工具真执行出闭环

- 命令输出(`uid=`/hostname 等)回显 = 工具真执行,但仅证执行,不计成立。
- 云密钥(临时票/永久 AKSK,可查明账号)= 凭据泄露成立。
- 主体业务正文(对话历史/工单/密钥文件,非自身刚写入的标记)= 经 LLM 工具越权读成立。
- 须追查到云钥/主体正文方算闭环;仅命令输出不计成立。

## 四、误报

- 模型仅口头称执行,无实际命令输出。
- 沙箱拒命令、空工具列表。
- 对话口同样要求登录,与身份口同一道闸。
- 仅有 prompt 越狱、无工具执行(非本类——纯越狱不收)。
- 仅 curl 到公网(百度首页/ICP 号)即视为通达内网。
- 探针未发现 tool/url 等可用字段(除 `message`/`prompt` 外)→ 本类 N/A;有口仅出 `uid=`、追查不到云钥/主体正文 → 证伪即止,不应纠缠至取得 root。
