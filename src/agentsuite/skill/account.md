## 一、确认 | 认响应差异与字段可控性

1. **响应差异**:注册/登录区分"用户不存在"vs"密码错误"(响应不同→可枚举);注册检测 `phone`/`username`/`email` 是否已注册回 `exists:true`/不同提示。先发错号 vs 错密码看响应是否区分。
2. **字段可控性**:找回/改密流程 body 哪个字段(`phone`/`userId`/`account`)驱动目标账号,token 是否绑发起方。改目标字段看是否被拒。

## 二、绕过 | 枚举差异或找回链断裂才有攻击面 只给思路自由发挥

- **账号枚举**:注册/登录响应区分"用户不存在"vs"密码错误"→枚举有效账号;注册检测 `phone`/`email` 回 `exists:true`→枚举已注册号。
- **找回流程篡改**:发起找回(手机 A)取 token/链接 → 改请求 `phone`/`userId` 为 B → 改 B 的密码(任意账号重置)。token 绑 A 则改 B 被拒,试 token 不绑发起方的口。
- **注销号接管**:用已注销号码注册 → 登录原绑定账号;或改绑手机时验码发到旧号(旧号持有者接管)。
- **竞态(TOCTOU,token 复用)**:找回 token 用后失效,并发复用同一 token 改多号密码(校验与使用非原子);签到/邀请奖励一次性配额同请求 N 并发 → 多倍计数。
- **登录锁定绕过**:按 IP 计数锁定时轮换身份头(`X-Forwarded-For`/`X-Real-IP`/`Forwarded` 填假 IP 重置计数);按账号锁定则头无效,试突发并发。
- **未登录改密自助**:未登录改密口/首次设密/重置最后一步,body 旧密/验码置空或省略 → Success 改他人密(同一密再打报"历史重复/错码"=已写库)。区别于"找回篡改"(那个改 phone 为 B,这个省略旧密/验码字段)。
- **SSO 壳后账密**:管理后台前端跳 SSO,后端暴露本地账密 API(`/admin-api/system/auth/login`)→ POST 默认 `admin`/`123456` → accessToken 打 `tenant`/`user page` 出他人手机/姓名。
- **IDaaS 改密链**:拿 sq 类 token(scope=`_`)→ GET 已绑 id → `update_question` 写未占用 id → `verify` 换 reset scope → `set_password`(改绑他人号)。

## 三、证明 | 改密只测自己号或能改回的 别真改他人密码

- 枚举:枚举到有效账号即成立(不真登录他人号)。
- 找回篡改:改 B 的密码成功 = 任意账号重置成立。改密只测自己号或能改回的测试号,过了立刻改回,不真改他人密码。
- 注销接管:接管他人账号(登录成功)即成立。
- 并发:同一 token 改多号成功 / 多倍到账即成立(须可复现)。
- SSO壳/改密自助/IDaaS链:改他人密成功 / accessToken 打管理口出他人数据 / 改绑他人号成功 = 成立。改密只测自己号或能改回的,过了立刻改回。

## 四、误报

- 响应统一不区分(无法枚举);找回 token 绑 A 改 B 的 `phone` 被拒。
- 注销号未重新分配、改绑需双端确认。
- 并发 N 份只 1 成功其余"已领/duplicate key"=有 UNIQUE 保护、counter 原子自增。
- 限流按账号不按 IP、counter 原子自增。
- SSO壳后账密口 404/默认口已改/票只能进空租户;改密要真旧密/真短信验码;Success 但密没跟过去(另一套)。
