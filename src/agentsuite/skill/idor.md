## 一、漏洞确认 | 删除相关字段确认后端是否由前端字段空
- **删除相关字段**: 确定接口是否由请求的字段响应, 如果删除没有影响, 大概率不存在越权, 是误报

## 二、类型确认 | 确认 id 类型 是否可以遍历
1. **可遍历(数字 / 号段)**:
 - `手机号`/`openid`/`pin`;
 - 能 `±1`/`±10`/邻号/`0`/`-1`/`999999` 爆破
 - 时间戳部分可以遍历
2. **不可遍历(UUID / 密文 / nodeId / openid / session_id)**:
 - 可以尝试爆破
 - 流量全局搜索这个id最早从哪里出现, 如果是响应a, 观察请求a相关字段是否可遍历; 如果是请求a, 可能是前端加密, 有概率存在
 - 响应体/列表 total/详情/评论消息/关联接口里复制他人 id; 观察id形态是否可以构造相邻

## 三、绕过思路 | 前提确认字段影响后端 | 可尝试Fuzz
1. 校验绕过(报无权限时):校验在 path→改 path 段;在 body→改字段位置/编码;在 header/cookie→改头;参数污染同名参两次。
2. 编码绕过:
  - 数字→16进制(0x3039)/8进制/科学计数法
  - URL 编码/双重编码(%31%32%33%34%35)
  - 类型混淆:数字↔字符串↔浮点(12345 / "12345" / 12345.0),JSON 体最灵
  - Base64/HEX 包一层;大小写混用(hex/UUID 大小写不敏感时)
  - 分号/逗号拼接(userId=A;B、userId=A,B);零宽字符插值

## 四、漏洞证明
越权(IDOR/BOLA):换对象 id 读/写他人资源,或低权调高权口。先认 id 类型,再换号看后端反应。
**最小可行:** 默认读/列表差分证明跨用户·跨租户。写越权要测,按「先加自己的 → 再删自己加的」;没有创建口只有改/删现成对象时,改一个**自己能改回去**的测试字段,请求一次就停,过了立刻改回。禁止批量改删、禁止真资损、禁止对着别人已有主数据试删。**不是**「写 IDOR 不测」,是最小证伪。

## 五、误报场景
- 后端虽然存在敏感信息, 但是是用户自己的
- 邻号仍是同一套公开接口、只出公开目录。
- 服务端按会话过滤(换了仍只回自己)、接口要真登录/签名。
- `phone` 一律空或只出测试号、只出虚拟号/中间号、suggest 只出公司名。
